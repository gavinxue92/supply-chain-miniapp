# 领域文档

本仓库的工程 Skill 在探索代码库时应如何使用领域文档。

## 探索前应阅读

- 根目录中的 `GLOSSARY.md`；若存在 `GLOSSARY-MAP.md` 则先读它并顺着指向找到对应上下文的词汇表。
- `docs/adr/` 中与即将处理主题相关的 ADR。

若这些文件不存在，静默跳过，不要提前建议创建。术语或决策真正明确时，由 `domain-modeling` Skill 按需创建。

## 文件结构

单上下文：

```text
/
├── GLOSSARY.md
├── docs/
│   └── adr/
└── src 或 pages/
```

## 使用词汇表

工单标题、方案、假设与测试名称涉及领域概念时，必须使用 `GLOSSARY.md` 中定义的术语，不要使用其中明确“避免”的同义词。

若词汇表缺少所需概念，先考虑是否引入了不必要的新术语，再标记可能的术语缺口。

## ADR 冲突

若方案与现有 ADR 冲突，必须明确指出，而不是静默覆盖。
