# ADR-0004：初版视觉以原型为准，展示层与逻辑解耦

**Status:** accepted
**Date:** 2026-11-20

## Context

用户要求 V1 直接按当前美团风格原型实现，后期再重新设计 UI。这既要求快速交付可评审的界面，又要求未来的换皮成本足够低。若把数据获取、状态逻辑和样式混在页面里，后期重设计会变成全量重写。

## Decision

初版视觉以 `prototype/index.html` 为唯一基线，代码评审按原型验收外观。工程上把展示层与数据、逻辑、配置分离：`pages/`、`components/`、`assets/` 承载外观；`types/`、`api/`、`utils/`、`config/` 承载契约与逻辑，不因换皮而变动。后期 UI 重设计作为独立工作，走 `grilling` / `to-spec` / `to-tickets` / `implement` 流程，只改展示层与样式，不碰公开接口接缝与业务规则。

## Consequences

- 初版视觉不是终态；评审时“像原型”是验收项，但不会把样式写成不可变约束。
- 后期重设计不需要后端改动，也不需要重写数据逻辑。
- 若视觉变化改变页面可观察行为，需补对应接缝测试。
- 展示层必须组件化；把样式和请求写在同一处的实现会在后期重设计时付出额外成本。
